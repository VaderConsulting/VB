Microsoft Windows Installer

LockPermissions Table

The LockPermissions table is used to secure individual portions of your application in a locked down environment. It can be used with the installation of files, registry keys, and created folders. If the folder, file, or registry key already exists, any access control lists (ACLs) are replaced by the entries in this table.

The LockPermissions table has the following columns.

Column Type Key Nullable
LockObject Identifier Y N
Table Text Y N
Domain Formatted Y Y
User Formatted Y N
Permission DoubleInteger Y

Columns

LockObject
This column and the Table column together specify the file, directory, or registry key that is to be secured. The LockObject column is a foreign key pointing into the primary key of the table specified by the Table column.
Table
This column and the LockObject column specify the file, directory, or registry key that is to be secured. In the Table column, enter either File, Registry, or CreateFolder to specify a LockObject listed in the File table, Registry table, or the CreateFolder table.
Domain
Specifies the domain of the user for which permissions are to be set. This is the name of a stand-alone machine or a domain name.
User
Specifies the localized name of the user for which permissions are to be set. This name must be located on the machine or domain. No permission is granted if the machine or domain controller does not recognize the domain and user combination or if the user's SID cannot be retrieved. Multiple users can be specified for a single LockObject. Examples of common user names are "Everyone," "Users," and "Administrators." LocalSystem is given full control in all security descriptors created through the LockPermissions table.

Note that you can use multiple records with identical LockObject and Table entries (but different User entries) to specify access control lists for multiple users.

Permission
An integer description of system privileges. The following gives the most commonly used values and a complete list exists in WINNT.H.
Privilege constant Hexadecimal Decimal
GENERIC_ALL 0X10000000 268435456
GENERIC_EXECUTE 0X20000000 536870912
GENERIC_WRITE 0X40000000 1073741824

Note that you cannot specify GENERIC_READ in the Permission column. Attempting to do so will fail. Instead, you must specify a value such as KEY_READ or FILE_GENERIC_READ.

Null entered in this column is reserved for future use.

Remarks

It is recommended that the system administrator's local group be included in all access control lists. This ensures that the system administrator will be able to access and maintain objects.

If a file, registry key, or directory is not listed in the LockPermissions table it receives no explicit security descriptor.

Every file, registry key, or directory listed in the LockPermissions table receives an explicit security descriptor. The installer also attempts to preserve the security on objects that already exist on the system. If a file, registry key, or directory replaces a secured object, it receives the security descriptor of the object it replaces. If the object is new, or if the object it replaces had no explicit security descriptor, access to the new object is based on the attributes of its parent or container object. The security settings of child registry keys are determined by the parent registry key and the security settings of files are determined by their directory. In general, it is not recommended to secure individual files and registry keys. Instead secure the directories or top level registry keys for your product or user. Access to a file is then automatically determined by the directory that contains it and access to a registry key is determined by the parent key.
