Microsoft Windows Installer

About the User Interface

The Microsoft® Windows® Installer contains functionality which enables installation package developers to author a graphical user interface (GUI) that is displayed to the end user during installation. This user interface can exhibit User Interface Wizard Behavior, display dialog boxes and billboards, and present interactive controls to users during the installation.

The Windows Installer internal user interface is managed and controlled through a set of database tables within Windows Installer itself. The installer provides only a small set of default dialog boxes which are intended to handle error and information messages. All custom dialog boxes must be created by the package author.

There is no specific Windows Installer API to allow a package author to create a user interface programmatically. It is possible to use the Microsoft Windows API to create a user interface programmatically; however, it is recommended that package authors use the internal user interface provided.

Installer package authors create custom dialog boxes by entering the name of their custom dialog into the "_Dialog" column of the dialog table and specifying the size, position, and other attributes using the remaining columns.

Windows Installer also implements a number of standard controls that a package author can place onto Dialog Boxes. Not all standard Microsoft Windows controls are available, and custom controls cannot be created for use with the Windows Installer user interface.

Controls are created on a specific dialog box by entering the name of the dialog box, which is the primary key to the dialog box's entry in the dialog table, into the second field of the control table and specifying the control's size, position and other attributes using the remaining columns.

Active controls must be linked to a ControlEvent in the ControlEvent table to allow user interaction with the installation. Passive controls that receive and display information must be subscribed to an appropriate ControlEvent in the EventMapping table.

For more information about ControlEvents, see ControlEvent Overview. Note that a control publishes a ControlEvent if listed in the ControlEvent table and subscribes to an event if listed in the EventMapping table.

The Windows Installer user interface display during installation is managed through the user interface sequence tables: InstallUISequence Table, AdminUISequence Table, and AdvtUISequence Table .One of these three sequence tables is executed depending on the top level action that initiated the installation: INSTALL, ADMIN, or ADVERTISE.

For more information about implementing a user interface in Microsoft Windows Installer, please see Using the User Interface, User Interface Schema, as well as the individual topics for Dialog boxes and Controls.
