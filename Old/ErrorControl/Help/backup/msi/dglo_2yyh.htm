Microsoft Windows Installer

A

accessibility
Design practice for making the installer's user interface accessible to all users. For more information about accessibility, see the overview topic: Accessibility.
acquisition phase
The phase of the installation during which the installer determines the installation procedure. It begins when an application or user instructs the Windows Installer to install an application or feature. The installer then queries the database for information as it generates the execution script for the installation. For more information about the phases of an installation, see Installation Mechanism.
action
Many of the functions performed by the Windows Installer are encapsulated into actions. Each action specifies the execution of a particular function and the total procedural flow of the installation is prescribed by the sequence of actions in the sequence tables. Standard actions are built into the Windows Installer and custom actions are written by the author of the installation package.
advertising
The capability of the installer to make the interfaces required for loading and making an application available without installing the application. When a user or application activates an advertised interface the installer then proceeds to install the necessary components. The two types of advertising are assigning and publishing. See also install-on-demand. For more information about how the installer advertises applications, see Advertisement.
assigning
Assigning makes an application available, and appear as if it has been installed to a user, without actually installing it. Assigning adds shortcuts and icons to the Start menu, associates the appropriate files, and writes the registry entries for the application. If a user tries to open an assigned application, the installer then installs the files of the application. Assigning and publishing are two methods of advertising. For more information about how the installer advertises applications, see Advertisement.
asynchronous execution
During an asynchronous execution of a custom action the installer runs the separate threads of the custom action and the current installation simultaneously. For more information, see the overview topic: Synchronous and Asynchronous Custom Actions.
