cabinet file
A cabinet is a single file, usually with a .cab extension, that stores compressed files in a file library. The cabinet format is an efficient way to package multiple files because compression is performed across file boundaries, significantly improving the compression ratio. For information about creating cabinets, see Cabinet Files.
checksum
A computed value that depends on the contents of a file and is stored with the data to detect corruption of the file's data. The system checks this value to provide confidence that the data is uncorrupted.
component
The smallest piece of an installation handled by the installer, also a building-block of an application or feature from the programmer's perspective. Examples of components are a group of related files, a COM object, or a library. For more information about components, see Components and Features.
committing databases
Changes made in a database are accumulated and are not reflected in the actual database until you commit the database. For more information, see Committing Databases.
ControlEvent
A part of the functionality of the installer's user interface. A typical ControlEvent triggers some action by the installer upon the activation of a dialog box control or some other event. For more information about using ControlEvents, see ControlEvent Overview.
costing
Costing is the method used by Microsoft Windows Installer to determine the disk space required by all the components in an installation. Costing takes into account factors such as whether existing files need to be overwritten. For more information about costing, see File Costing.
.cub file
A .cub file is a validation module that stores and provides access to ICE custom actions. See Sample .cub File. See also Windows Installer File Extensions.
custom action
An action that is written by the author of the package and that is not built into the installer as a standard action. For more information about custom actions, see Custom Actions.
