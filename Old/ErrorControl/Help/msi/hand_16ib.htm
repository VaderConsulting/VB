Parsing Windows Installer Messages

When MsiSetExternalUI is called, the second parameter contains a list of installer messages that the external user interface handler will process. In many cases, the external UI handler filters for certain messages but will not handle them. Using this method, an external user interface handler can monitor the installation without affecting the installation in any way.

Windows Installer messages contain a string that in certain cases must be parsed before it is useful.

The following list of Windows Installer messages contain simple string messages that can be displayed directly using a dialog box. As discussed in Returning Values from an External User Interface Handler, Windows Installer messages also contain a list of buttons and icons that should be displayed by the dialog box. The MB_ICONMASK, MB_DEFMASK, and MB_TYPEMASK values can be used to determine the icons and default buttons.

Windows installer message Meaning of string data
INSTALLMESSAGE_FATALEXIT Premature termination of installation has occurred. No processing of string required, it can be displayed directly.
INSTALLMESSAGE_ERROR Formatted error message. No processing of string required, it can be displayed directly.
INSTALLMESSAGE_WARNING Formatted warning message. No processing of string required, it can be displayed directly.
INSTALLMESSAGE_INFO Formatted log message. No processing of string required, it can be displayed directly.
INSTALLMESSAGE_USER Formatted user message. No processing of string required, it can be displayed directly.
INSTALLMESSAGE_OUTOFDISKSPACE Formatted message indicating an out of disk space condition. No processing of string required, it can be displayed directly

INSTALLMESSAGE_RESOLVESOURCE
An external user interface handler may filter the INSTALLMESSAGE_RESOLVESOURCE message, but it should not act upon it. Instead, the external user interface handler must return 0 and allow Windows Installer to handle the message.
INSTALLMESSAGE_FILESINUSE
An external user interface should display a FilesInUse dialog in response to the INSTALLMESSAGE_FILESINUSE message.
INSTALLMESSAGE_ACTIONSTART
The format of this string is Action [1]: [2]. [3] where:

[1] is the TIME the action started

[2] is the name of the action (from the particular Sequence table)

[3] is the description of the action (as described in the Description column of the ActionText table or established via a MsiProcessMessage call)

For example:

Action 16:31:56: RemoveRegistryValues. Removing system registry values

INSTALLMESSAGE_ACTIONDATA
The format follows the ActionTemplate provided in the template column of the ActionText table for the particular action or as established by a MsiProcessMessage call. After an ACTIONSTART message, any number of ACTIONDATA messages, from 0 and up, can be received.
INSTALLMESSAGE_COMMONDATA
There are three types of CommonData messages: Language, Caption, and CancelShow.

CommonData messages can have up to three fields. A field is designated by a number followed by a colon. Field 1 is "1:<data>". Field 2 is "2:<data>". Not all fields are required to be present and at times a CommonData message may be a NULL or blank ("") string.

Language
For example:    1:0    2:1033    3:1252

Field 1: 0 // The '0' in this field indicates that common data message is of type Language.

Field 2: LANGID // In the above example, the LANGID is 1033 for English.

Field 3: CodePage // In the above example, the CodePage is 1252, a US ANSI codepage.

Caption
For example:    1:1    2:TestDb    3:NULL

Field 1: 1 // The '1' in this field indicates that common data message is of type Caption.

Field 2: TestDb // In the above example, the Caption is TestDb. The external UI handler might use this string as the Caption/Title for Dialogs and MessageBoxes.

Field 3: NULL // Field 3 may or may not always be a part of the string.

CancelShow
For example:    1:2    2:1

Field 1: 2 // The '2' in this field indicates that common data message is of type CancelShow.

Field 2: 1 // A value of '0' indicates the cancel button should be hidden. A value of '1' indicates the cancel button should be visible. In the above example, this value literally means "Show/Enable the cancel button".

INSTALLMESSAGE_PROGRESS
There are four types of Progress messages: Reset, ActionInfo, ProgressReport, and ProgressAddition. Depending upon the previous execution state, the progress bar may either need to be reset or completed. Any external handler code should not act upon any initial progress messages until the first "Reset" progress message has been received and established the total number of ticks for the progress bar.
Reset
Field 1: 0 // A '0' indicates that the progress bar should be reset

Field 2: // Contains the expected total number of ticks in progress bar.

Field 3: // Indicates direction of progress bar movement. '0' = forward, '1' = backward.

Field 4: // Indicates execution state. '0' = in progress, time remaining calculation can be made, '1' = begin of script, a "Please wait ..." message can be displayed.

ActionInfo
Field 1: 1 // A '1' indicates the string contains action information.

Field 2: // Contains the number of ticks the progress bar moves for each ActionData message received.

Field 3: // If this field is '0', field 2 should be ignored. If this field is '1', increment the progress bar by the number of ticks specified in field 2 for each ActionData message received.

Field 4: // Unused.

ProgressReport
Field 1: 2 // A '2' indicates the string contains progress information.

Field 2: // Contains the number of ticks the progress bar has moved.

Field 3: // Unused.

Field 4: // Unused.

ProgressAddition
Field 1: 3 // A '3' indicates that an action can add ticks to the progress bar.

Field 2: // Contains the number of ticks to add to total expected progress ticks.

Field 3: // Unused.

Field 4: //Unused.

The following Windows Installer messages refer to the Windows Installer user interface and provide a way for an external user interface handler to monitor a Windows Installer sequence. The external user handler is notified by the installer at the start of user interface sequence, as each dialog is presented, and at the end of user interface sequence.

INSTALLMESSAGE_TERMINATE
The string is a NULL string. No processing is required. This message indicates the end of the user interface sequence.
INSTALLMESSAGE_INITIALIZE
The string is a NULL string. No processing is required. This message indicates that the user interface sequence has started.
INSTALLMESSAGE_SHOWDIALOG
The string contains the name of the current dialog. No processing is required.
