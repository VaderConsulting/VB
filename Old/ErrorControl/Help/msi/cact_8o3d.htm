Custom Action Security

The installer runs custom actions with user privileges by default in order to limit the access of custom actions to the system. The installer may run custom actions with elevated privileges if a managed application is being installed or if the system policy has been specified for elevated privileges.

Note that only deferred execution custom actions can use the msidbCustomActionTypeNoImpersonate attribute. For more information see Custom Action In-Script Execution Options.

Windows 2000

For Microsoft® Windows® 2000, if the msidbCustomActionTypeNoImpersonate bit is not set for a custom action, the installer runs the custom action with user-level privileges. For more information, see Custom Action In-Script Execution Options.

If the msidbCustomActionTypeNoImpersonate bit is set and a managed application is being installed with administrator permission, the installer may run the custom action with elevated privileges. However, if a user attempts to install the managed application without administrator permission, the installer runs the application with user level privileges regardless of whether msidbCustomActionTypeNoImpersonate is set.

Note that a custom action may run with system privileges even when the msidbCustomActionTypeNoImpersonate bit is not set. This occurs if an administrator installs the application for all users on a computer using Windows 2000 Terminal Server. This also occurs if the installation is invoked when there is no user context. For example, if there is no currently logged-on user during an installation invoked by Windows 2000 Application Deployment.

Windows NT

For Microsoft Windows NT® 4.0, if the msidbCustomActionTypeNoImpersonate bit is not set for a custom action, the installer runs the custom action with user level privileges. For more information, see Custom Action In-Script Execution Options.

Note that a custom action may run with system privileges in cases where the installation is invoked without an associated user context, even when the msidbCustomActionTypeNoImpersonate bit is not set.

If the msidbCustomActionTypeNoImpersonate bit is set, and the AlwaysInstallElevated policies are set, the installer may run the custom action with elevated privileges.
