Patch Packages

Microsoft® Windows® Installer uses a patch package to patch local or administrative installations. A patch package is a storage file, similar to a descriptor file, and has a .msp file name extension and its own CLSID. Patch packages are comprised of a summary information stream, transform substorages, and cabinet file streams.

A patch package does not include a database like a regular installation package. Instead it contains at minimum one database transform that adds patching information to the database of its target installation package. The installer uses this information to apply the patch files that are stored in the cabinet file stream of the patch package. For more information, see Creating a Patch Package.

Windows Installer version 1.0 allowed users who were not administrators to apply patches to applications being installed with elevated privileges. This has changed for Windows Installer version 1.1 so that only an administrator can apply a patch to an installation with elevated privileges. Non-administrator users can still apply a patch to applications not being installed with elevated privilege. If the AllowLockdownPatch policy has been set, non-administrator users can apply a patch to an existing product while running an installation at elevated privileges.

Patch packages are comprised of the following parts.

Summary Information Stream

The summary information stream holds a minimum of the following:

  • A GUID that uniquely identifies the patch. The GUID for this patch is appended with a list of GUIDs for earlier patches that are replaced by this patch.
  • A semicolon-delimited list of product codes for valid targets for this patch.
  • A semicolon-delimited list of transform substorage names in the order they are to be applied.
  • A semicolon-delimited list of sources for this patch.

Transform Substorage

Transforms are used to update an application's database. Transforms can add or remove new files, registry entries, user interfaces, or customizations. Transforms are included in a patch package as substorage. Each substorage has its own summary information stream.

Two transforms are stored in the patch for each target database, and more than one pair of transforms can be in a patch if there are multiple targets. The first transform modifies the target to the new version. The second transform adds entries to the Patch, PatchPackage, Media, InstallExecuteSequence, and AdminExecuteSequence tables that provide file patching instructions to the installer.

The installer applies the transforms during a network administrative installation, and the changes then persist in the administrative image of the application's installer package. If the target is a local installation, however, the installer reapplies the transforms each time a maintenance mode or uninstall installation is invoked.

Cabinet File Stream

The cabinet file stream included in a patch can contain three types of files:

  • Patch files containing the information required to change the old version of the file into the new version. A single patch file can be used to update one or more old versions of a file.
  • Additional files being added to the application that are not present in the old version.
  • A entire replacement file. In the rare case where the new version of a file is smaller than the patch required to update the old version of that file, the new file can be included in its entirety. These are new files that are installed over their old versions.
