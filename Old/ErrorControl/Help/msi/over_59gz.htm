Platform SDK: Windows Installer

Using 64-Bit Windows Installer Packages

Setup developers should do the following when creating 64-bit Windows Installer Packages or applications that call the Windows Installer to install 64-bit packages:

  • Use a Windows Installer database schema of 200 or higher. Specify that version 2.0 is the minimum version of the Windows Installer required to install the package by setting the Page Count Summary Property to the integer 200. Earlier Windows Installer versions reject attempts to install 64-bit packages.
  • Indicate in the package's summary information stream that this is a 64-bit package. Enter "Intel64" into the platform field of the Template Summary Property. A package cannot be neutral, and this summary property must never have "Intel64" entered together with "Intel" (or "Alpha" for Windows Installer version 1.0).
  • Identify every 64-bit component by setting the msidbComponentAttributes64bit in the Attributes column of the Component table.
  • Use optional conditional statements that check the version of the 64-bit operating system by referencing the VersionNT64 property. Windows Installer version 2.0 sets this property to the 64-bit Windows version and leaves VersionNT64 undefined if the operating system is not 64-bit Windows. For details, see Using Properties in Conditional Statements.
  • Use optional conditional statements that check the numeric processor level of the computer by referencing the Intel64 property. Windows Installer version 2.0 sets this property to the current numeric processor level of the computer and leaves Intel64 undefined if this is not an Itanium-based processor. For details, see Using Properties in Conditional Statements.
  • Use the AppSearch table and AppSearch action to do optional searches of the registry for existing 64-bit components. To search for existing 64-bit components, include the msidbLocatorType64bit bit in the Type column of the RegLocator table. For details, see Searching for Existing Applications, Files, Registry Entries or .ini File Entries
  • Obtain the paths to system folders by referencing the System64Folder property, ProgramFiles64Folder property, and CommonFiles64Folder property for the 64-bit folders and the SystemFolder property, ProgramFilesFolder property, and CommonFilesFolder property for the 32-bit folders.
  • Verify that the application uses the correct GUID when referencing a 64-bit component. If there are 32-bit and 64-bit versions of particular component, these should have different component ID GUIDs.
  • Determine whether any new environment variables need to be defined when installing 64-bit applications.
  • Verify that the application only calls 32-bit services that run as executables. Applications should not call 32-bit services that run in DLLs.
  • If the application installs coexisting 32-bit and 64-bit versions of a component, verify that the application share .ini file information correctly.
  • Verify that the application only applies 32-bit patches to 32-bit binaries and 64-bit patches to 64-bit binaries.
  • Application developers should consider future upgrade scenarios for both 32-bit and 64-bit versions and maintain upgrade codes. For details, see Patching and Upgrades.

For more information, see 64-Bit Custom Actions.
