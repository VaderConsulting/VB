Platform SDK: Windows Installer

MsiDatabaseMerge

The MsiDatabaseMerge function merges two databases together, allowing duplicate rows. For information on attaching a merge module to an installation package, see Merge Modules.

UINT MsiDatabaseMerge(
  MSIHANDLE hDatabase,      // database handle
  MSIHANDLE hDatabaseMerge, // database to be merged into hDatabase
  LPCTSTR szTableName       // name of persistent table to receive rows
);

Parameters

hDatabase
[in] Handle to the base database.
hDatabaseMerge
[in] Handle to the database to merge into the base database.
szTableName
[in] Specifies the name of the table to receive merge conflict information.

Return Values

ERROR_FUNCTION_FAILED
Row merge conflicts were reported.
ERROR_INVALID_HANDLE
An invalid or inactive handle was supplied.
ERROR_INVALID_TABLE
An invalid table was supplied.
ERROR_SUCCESS
The function succeeded.
ERROR_DATATYPE_MISMATCH
Schema difference between the two databases.

Remarks

MsiDatabaseMerge does not copy over embedded cabinet files or embedded transforms from the reference database into the target database. Embedded data streams that are listed in the Binary table or Icon table are copied from the reference database to the target database. Storage embedded in the reference database are not copied to the target database.

The MsiDatabaseMerge function merges the data of two databases. These databases must have the same codepage. MsiDatabaseMerge fails if any tables or rows in the databases conflict. A conflict exists if the data in any row in the first database differs from the data in the corresponding row of the second database. Corresponding rows are in the same table of both databases and have the same primary key in both databases. The tables of non-conflicting databases must have the same number of primary keys, same number of columns, same column types, same column names, and the same data in rows with identical primary keys. Temporary columns however don't matter in the column count and corresponding tables can have a different number of temporary columns without creating conflict as long as the persistent columns match.

If the number, type, or name of columns in corresponding tables are different, the schema of the two databases are incompatible and the installer will stop processing tables and the merge fails. The installer checks that the two databases have the same schema before checking for row merge conflicts. If ERROR_DATATYPE_MISMATCH is returned, you are guaranteed that the databases have not been changed.

If the data in particular rows differ, this is a row merge conflict, the installer returns ERROR_FUNCTION_FAILED and creates a new table named szTableName. The first column of this table is the name of the table having the conflict. The second column gives the number of rows in the table having the conflict. The table reporting conflicts appears as follows.

Column Type Key Nullable
Table Text Y N
NumRowMergeConflicts Integer   N

The following behavior only applies in Windows Installer version 1.1:

When merging a table, if a column containing string data has an identical type between the two databases with the sole exception of differing length limits, the table after the merge will have the larger of the two limits. If either of the columns has no limit (the limit is 0), then the column after the merge has no limit.

This function cannot be called from custom actions. A call to this function from a custom action causes the function to fail.

Requirements

  Windows NT/2000/XP: Included in Windows 2000 and later.
  Windows 95/98/Me: Included in Windows Me.
  Redistributable: Requires Windows Installer 1.0 or later on Windows NT 4.0 SP3 and Windows 95/98.
  Header: Declared in Msiquery.h.
  Library: Use Msi.lib.
  Unicode: Implemented as Unicode and ANSI versions on all platforms.
