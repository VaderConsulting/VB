Platform SDK: Windows Installer

Code Page Handling of Parameter Strings

Authors may add localization information to an installation database by using a database table editor such as Orca, provided with the Windows Installer SDK, or by calling the Database Functions from a program. Authors must be careful to only pass string parameters that use the code page of the database that is being localized. If a string parameter contains characters that cannot be represented by the code page of the database, the installer returns an error when calling MsiDatabaseImport. See Determining an installation database's code page and a list of numeric code pages see Localizing the Error and ActionText Tables.

Windows 98 and Windows 95

When adding localization information to a database using Windows 95 or Windows 98, the code page of the database must be neutral or it must match the current code page of the system. In this case, the strings passed to the Database Functions must be code-page neutral or require the same code page as the database.

Windows NT and Windows 2000

When adding localization information to a database using Windows NT or Windows 2000, the code page of the database must be supported by the system. It does not have to be the current code page of the system. IsValidCodePage must return TRUE for the database's code page. Note that because Windows NT and Windows 2000 convert ANSI strings to Unicode, there is an error if the current user's code page is not the same as the database's code page.

Calling the ANSI version of the Windows Installer API on Windows NT or Windows 2000 converts the localized string to Unicode using the current system code page. When the database is committed, the Unicode string is converted to ANSI using the code page of the database. This can result in a loss of data and incorrect string conversion if the current system's code page differs from the code page of the localized string. The following procedure will ensure that the localization data is properly stored.

  1. Set the code page of the database to the code page of the localized string.
  2. Convert the ANSI string to Unicode using the Win32 function MultiByteToWideChar and specify the code page of the localized data.
  3. Call the Unicode version of the Windows Installer API with the Unicode string to add the localized data.
  4. Commit the localization changes to the database with MsiDatabaseCommit.

Authors may also add localization information to an installation database by importing and exporting ASCII text archive files. For more information, see Code Page Handling of Imported and Exported Tables.
