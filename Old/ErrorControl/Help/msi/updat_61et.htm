Major Upgrades by Patching an Administrative Image

An administrative installation creates a source image of an application or product on a network. Users in a workgroup who have access to this administrative image can install the product from this source. Upgrading the application for this workgroup is done in two steps. First, the major upgrade patch can be applied to the administrative image. Second, the changes in the major upgrade need to be propagated to the users.

To apply a Small Update patch to an administrative image

  1. Obtain the major upgrade in the form of a patch package. For example, the major upgrade named Patch.msp.
  2. Obtain the path to the administrative image.
  3. From the command line use: msiexec /a [path to administrative image .msi file] /p patch.msp . This updates the application files and the .msi file of the administrative image. For a list of the options that can be used with Msiexec.exe, see Command Line Options. If during the original administrative installation SHORTFILENAMES was set to 1, and you are using an installer version earlier than Windows Installer version 2.0, you must also pass the SHORTFILENAMES property when applying the major upgrade patch. Windows Installer version 2.0 or later versions automatically determine whether the administrative image is using short file names and sets the SHORTFILENAMES property.
  4. The resulting administrative image is the same as that produced by an administrative installation using a full product CD-ROM that includes the upgrade. When new users install the application from this source they receive the upgraded application.

To propagate the Small Update to the workgroup

  1. Members of the workgroup obtain the changes by reinstalling the application from the administrative image using the procedure described in Small Updates by Reinstalling the Product.
