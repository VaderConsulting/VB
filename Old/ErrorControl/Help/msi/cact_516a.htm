Adding Custom Actions to the ProgressBar

Custom Actions can add time and progress information to a ProgressBar control. For more information about creating an action display dialog box, see Authoring a Progress Bar Control.

A custom action must add ticks to the total tick count during the acquisition and script generation phase of the installation. An immediate execution custom action must be scheduled in the sequence table after any standard action that generates script records, such as:

InstallValidate action
InstallInitialize action
ProcessComponents action

The following example code fragment is used in the immediate execution custom action to add the ticks to the total tick count.

MSIHANDLE hEngine = NULL;
UINT iResult = MsiOpenPackage("c:\MyPackage.msi", &hEngine);
// Error handling code
PMSIHANDLE hRec = MsiCreateRecord(3);
MsiRecordSetInteger(hrec, 1, 3);        // ProgressAddition subclass
MsiRecordSetInteger(hrec, 2, 24000);    // Add 24000 ticks to the current progress total
iResult = MsiProcessMessage(hInstall, INSTALLMESSAGE_Progress, hRec);
// Error handling code

A deferred execution custom action is required to send the individual tick amounts to the ProgressBar control during installation. The code required to accomplish this is similar to the prior example with the exception that the MsiRecordSetInteger function would be used to set the correct field of the record created with the MsiCreateRecord function to the ProgressReport value.

The amount of ticks reported by this deferred execution custom action must be equal to the number of ticks added to the total tick count by the immediate execution action or the time remaining reported by the TimeRemaining text control is inaccurate.

To add a custom action to the progress bar

  1. Decide how to describe the progress of the custom action in terms of reference items as they are installed on the target media. For example, a custom action that installs registry keys can display a progress message and update the progress bar each time the installer writes one registry key.
  2. In the following steps you need to refer to the progress bar's final total length, and its change in length in terms of arbitrary units called 'ticks'. Base the tick units in your custom actions on the number of bytes installed on the target media. Usually, a change in progress bar length of one tick corresponds to the installation of a one byte of files.
  3. Each update of the control by the installer changes the length of the progress bar by a constant increment. Specify or calculate the number of ticks in one such increment. For example, if the installer installs approximately 13400 bytes when it writes one registry key, specify that an increment is 13400 ticks. Usually this information can be coded into the custom action.
  4. Specify or calculate the total number of ticks the custom action adds to the length of the progress bar. The installer needs this information at the time it generates the installation script to estimate the final total length of the progress bar. The number of ticks added by the custom action is usually calculated as: (bytes installed per reference item) x (number of reference items). For our example, if the custom action writes 20 registry keys, the installer installs approximately 268000 bytes and the installer must increase the estimate of the final total length of the progress bar by 268000 ticks. If the installer is to calculate this dynamically, the custom action must contain code that is immediately executed during script generation.
  5. Separate your custom action into three parts that run during the script generation, execution, and rollback phases of the installation.
  6. In the part of the custom action that runs during a rollback, insert code for any changes the custom action needs to make during a rollback.
  7. In the part of the custom action that runs at the time the installer is generates the installation script, tell the installer to increase the estimate of the final total length of the progress bar by the total number of ticks in the custom action. You may also include any code here needed to calculate the total number of ticks added by the custom action.
  8. In the part of the custom action that runs during the execution phase of the installation, set up appropriate message text and templates that will inform the user about what the custom action is doing and the installer how to update the progress bar control. For example, inform the installer to move the progress bar forward one increment and send an explicit progress message with each update. There is usually a loop in this part of the custom action that installs something. For example, with each pass through this loop, the installer can install one reference item such as a registry key and update the progress bar control.

The following sample shows how a custom action can be added to the progress bar. The sample installs 1000 reference items that are each approximately 10000 bytes in size. The installer updates the message and indicator displayed by the progress bar control each time it installs a reference item.

#include <windows.h>
#include <msiquery.h>
 
    // Specify how many ticks there are in one length increment. This
    // is usually hard coded into the custom action and a change in
    // length of one tick usually corresponds to the installation of
    // one byte of files. For this sample, a length change of one
    // increment is 10000 ticks and corresponds to 10000 bytes.
 
const UINT iTickIncrement = 10000;
 
    // Specify or calculate the total number of ticks the custom
    // action adds to the final total length of the progress bar.
    // This would usually be calculated as: (bytes per item
    // installed) x (number of items). For this sample:
    // (10000) x (1000) is hard coded in as a constant.
 
const UINT iTotalTicks = 10000000;
 
UINT __stdcall CAProgress(MSIHANDLE hInstall)
{
    PMSIHANDLE hRec = MsiCreateRecord(3);
    PMSIHANDLE hProgressRec = MsiCreateRecord(3);
 
    // Tell the installer to check the installation state and execute
    // the code needed during the rollback, acquisition, or
    // execution phases of the installation.
 
  if (MsiGetMode(hInstall,MSIRUNMODE_ROLLBACK))
  {
    // Installer is rolling back the installation. Additional code
    // could be inserted here to enable the custom action to do
    // something during an installation rollback.
 
    return ERROR_SUCCESS;
  }
 
  if (!MsiGetMode(hInstall,MSIRUNMODE_SCHEDULED))
  {
    // Installer is generating the installation script of the custom
    // action. Additional code could be inserted here to enable the
    // installer to calculate the value of iTotalTicks during
    // script generation.
 
    // Tell the installer to increase the value of the final total
    // length of the progress bar by the total number of ticks in the
    // custom action.
 
    MsiRecordSetInteger(hRec,1,3);
    MsiRecordSetInteger(hRec,2,iTotalTicks);
    MsiRecordSetInteger(hRec,3,0);
    UINT iResult = MsiProcessMessage(hInstall, INSTALLMESSAGE_PROGRESS, hRec);
    return ERROR_SUCCESS;
  }
  else
  {
    // Installer is executing the installation script. Set up a
    // record specifying appropriate templates and text for messages
    // that will inform the user about what the custom action is
    // doing. Tell the installer to use this template and text in
    // progress messages.
 
    MsiRecordSetString(hRec,1,TEXT("Progress Custom Action"));
    MsiRecordSetString(hRec,2,TEXT("Incrementing the Progress Bar..."));
    MsiRecordSetString(hRec,3,TEXT("incrementing tick [1] of [2]"));
    UINT iResult = MsiProcessMessage(hInstall, INSTALLMESSAGE_ACTIONSTART, hRec);
 
    // Tell the installer to use explicit progress messages.
 
    MsiRecordSetInteger(hRec,1,1);
    MsiRecordSetInteger(hRec,2,1);
    MsiRecordSetInteger(hRec,3,0);
    iResult = MsiProcessMessage(hInstall, INSTALLMESSAGE_PROGRESS, hRec);
 
    // Specify that an update of the progress bar's position in this
    // case means to move it forward by one increment.
 
    MsiRecordSetInteger(hProgressRec,1,2);
    MsiRecordSetInteger(hProgressRec,2,iTickIncrement);
    MsiRecordSetInteger(hProgressRec,3,0);
 
    // The following loop sets up the record needed by the progress
    // messages and tells the installer to send a message to update
    // the progress bar.
 
    MsiRecordSetInteger(hRec,2,iTotalTicks);
    for( int i = 0; i<iTotalTicks; i+=iTickIncrement)
    {
      MsiRecordSetInteger(hRec,1,i);
      iResult = MsiProcessMessage(hInstall, INSTALLMESSAGE_ACTIONDATA, hRec);
      iResult = MsiProcessMessage(hInstall, INSTALLMESSAGE_PROGRESS, hProgressRec);
 
    // A real custom action would have code here that does a part of
    // the installation. For this sample, code that install 10000
    // bytes of files.

      Sleep(0);
    }
 
    return ERROR_SUCCESS;
  }
}
