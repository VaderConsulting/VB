MsiOpenPackageEx

The MsiOpenPackageEx function opens a package for use with functions that access the product database. The MsiCloseHandle function must be called with the handle when the handle is no longer needed. 

UINT WINAPI MsiOpenPackageEx(
  LPCTSTR szPackagePath,   // fully qualified path to package,
                           //  or database handle: #nnnn
  DWORD dwOptions,         // options flags to indicate whether
                           //  or not to ignore computer state
  MSIHANDLE *hProduct      // returned product handle, must be closed
);

Parameters

szPackagePath
[in] Specifies the path to the package.
dwOptions
[in] Bit flags to indicate whether or not to ignore the computer state. Pass in 0 to use MsiOpenPackage behavior.
Constant Value Meaning
MSIOPENPACKAGEFLAGS_IGNOREMACHINESTATE 1 Ignore the computer state when creating the product handle

hProduct
[out] Pointer to a variable that receives the product handle.

Return Values

Value Meaning
ERROR_BAD_CONFIGURATION The configuration information is corrupt.
ERROR_INSTALL_FAILURE The product could not be opened.
ERROR_INVALID_PARAMETER An invalid parameter was passed to the function.
ERROR_SUCCESS The function completed successfully.

If this function fails, it may return a system error code. For more information, see System Error Codes.

Remarks

MsiOpenPackageEx is available with Windows Installer version 2.0 or later.

To create a restricted product handle that is independent of the current machine state and incapable of changing the current machine state, use MsiOpenPackageEx with MSIOPENPACKAGEFLAGS_IGNOREMACHINESTATE set in dwOptions.

Note that if dwOptions is MSIOPENPACKAGEFLAGS_IGNOREMACHINESTATE or 1, MsiOpenPackageEx ignores the current machine state when creating the product handle. If the value of dwOptions is 0, MsiOpenPackageEx is the same as MsiOpenPackage and creates a product handle that is dependent upon whether the package specified by szPackagePath is already installed on the computer.

The restricted handle created by using MsiOpenPackageEx with MSIOPENPACKAGEFLAGS_IGNOREMACHINESTATE only permits execution of dialogs, a subset of the standard actions, and custom actions that set properties (Custom Action Type 35, Custom Action Type 51, and Custom Action Type 19). The restricted handle prevents the use of custom actions that run Dynamic-Link Libraries, Executable Files, Scripts, or Nested Installation Actions.

You can call MsiDoAction on the following standard actions using the restricted handle. All other actions return ERROR_FUNCTION_NOT_CALLED if called with the restricted handle.

ADMIN

ADVERTISE

INSTALL

The MsiCloseHandle function must be called when the handle is no longer needed.
